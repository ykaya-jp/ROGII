### 1.2 ★ 上位陣の本命アプローチ: DTW + 3D 地質構造再構築

- **topic 697431** (`besides regression, also dwt (time warping)!`, 16 votes, 16 replies、hengck23 など強者参戦)
- key insights (順序は post 順):
  1. 「stretch and fold で typewell に match」(geosteering の本質)
  2. 「test と train が地理的に近い → pure regression でも動く可能性」
  3. 「**train + test 全体で 3D 地質構造を再構築するのが winning move**」(複数 topic 提起)
  4. 「DTW で alignment、ただし **index reverse OK** (drillhead は up/down 双方向)、**local search に restrict**」
  5. 「forward model: `np.interp(h_tvt, tw_tvt, tw_gr)` で typewell から GR を generate して match」
  6. 「piece-wise DTW: model predict (start, end, dTVT/dMD slope) for each segment、ただし **DP cost matrix の方が良い**」
  7. 「**deep net logit**: `horizontal MD length × typewell location (each loc = class)` の transformer。anchor point first を期待」
  8. 「dTVT vs MD plot で **dy が constant** → synthetic data の可能性 (要追検)」
  9. 「3D plot で **folding 問題** として可視化される」
- **含意**:
  - 現状 `exp003` の WLS b_well + tasmim xcorr アプローチ (`feat/phase-2-exp003`) は **戦略 1 (xcorr) のみ** をカバー
  - 上位は **戦略 1 (DTW alignment) + 戦略 2 (3D 構造再構築 / multi-well joint inference)** の **2 段** を組み合わせる兆候
  - **NN logit approach** (horizontal MD × typewell loc class) は次の実験案として登録すべき (= 案 B Transformer の variant)

### 1.3 ★ TVT 定義: ROGII 公式が「imaginary reference line までの vertical distance」と確定

- **topic 698282** (`Definition of tvt`, 2 votes, 3 replies、**ROGII 公式回答 v=3**)
- 質問: 「TVT は depth？厚さ？何の thickness？」
- ROGII 公式回答 (msg4):
  - **TVT = vertical distance to a virtual/imaginary reference line**
  - **TVT=0 = ground level かは不明** (固定ではない)
  - **lateral の TVT は対応する typewell の TVT に対応する** (lateral-typewell pair ごとに)
  - **lateral の XYZ は真の空間座標**、**typewell は地質の vertical 定義 (GR values)**
- 別 user (PatrickAIForFun) の検証 (msg2): `ANCC - Z = TVT + offset` (offset は well ごと一定) → TVT reference は地質構造に追従
- **含意**:
  - 現状の dense doc (`docs/research/data-spec.dense.md`) は TVT を「depth-like」と暗黙に扱っているが、**正確には「地質構造に追随する仮想基準線からの vertical distance」**
  - **per-well offset** (TVT_input - Z_input の per-well median) は強力な特徴量
  - geological formation top (ANCC, ASTNU 等) を typewell から拾って `formation_top - Z = TVT + offset` の関係を解けば、**typewell-free な offset 推定**も可能 (将来の独立 baseline 案)

### 1.5 ★ 重要 caveat: 公開 test/ は dummy、本番 test は別物

- **topic 697507** (`Test well 000d7d20 also exists in train/`, 1 vote, 3 replies、**Kaggle staff 公式回答**)
- **topic 698266** (`Clarification on duplicate well IDs`, 0 votes, 1 reply)
- **topic 697857** (`Is 'Geology' feature included in actual test set?`, 0 votes, 2 replies)
- 内容: 公開 test/ は **example data (debugging 用)**、submission 時に **hidden test** に置換される。hidden test wells は **train に含まれない**。Geology 列は train typewell のみ。
- **含意**:

  - 戦略実装時に「公開 test の特徴量分布」を信用しない (本番 test は別物)
  - **Geology は train-only auxiliary supervision** に使うが、test 推論時には head を捨てる前提で設計

### 1.6 ★ Pseudo-typewell: 同一 typewell が複数 lateral に共有される

- **topic 698449** (`Duplicate type wells for different horizontal wells`, 2 votes, 2 replies、**ROGII 公式回答 v=2**)
- 13 セットの duplicate type wells 発見 (1 セットは **10 lateral wells が同一 typewell**: `02e7fe5a, 10b89021, 3417285d, 6ae68655, 7993a768, bc4381e2, ecdab904, f021b650, f49fdea3, f88ddb26`)
- ROGII 公式回答 (msg3):
  - geologist が手動で typewell 選定 (近い + 当時利用可能)
  - **「pseudo-typewell」= 隣接 lateral から作った interpretation を typewell として再利用**するケースがある
  - 「project 内 typewells の一部は実際には pseudo-typewell」
- **含意**:
  - **CV 設計に直接影響**: typewell ID で GroupKFold すると leakage する (異なる lateral が同じ typewell 共有 → train/val 分割で typewell が両側に出る)
  - **正しくは well_id で GroupKFold + さらに typewell hash で stratify** (同一 typewell の lateral 群は同一 fold に固める)
  - pseudo-typewell の lateral は **「他の lateral から推定された typewell」を真値として使う** → **誤差が typewell 内に既に乗っている** = ground truth 信頼度が下がる → 該当 well の loss weight を下げる検討

- **topic 697300** (`Some question`, 1 vote, 3 replies)
- 効くもの: GR log への小ノイズ追加、known zone のランダム短縮 (eval length variation simulation)
