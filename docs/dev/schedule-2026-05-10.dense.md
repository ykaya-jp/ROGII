### 0.3 新リスク (改修 b 固有)

1. **GP scalability** (案 E): 6 formation × 776 wells × 数百 obs = 数十万点で Sparse GP (SVGP, Hensman 2013) が必須。実装失敗時は plane-fit imputer に回帰
2. **Kalman 末端 drift** (案 D): φ < 1 で長距離 extrap すると 0 へ regress、bias 発生。対策: per-well per-formation で φ を fine fit、または piecewise linear b_well と組合わせ
3. **MoE cluster K 選択** (案 G): K=3 vs K=5 で効果が変わる。BIC / silhouette で auto-select、または hard cluster で fallback
4. **subagent kill 多発** (= 2026-05-10 の経験): 4 並列が全 kill された。**並列度を 2-3 に抑える**、各 subagent task の **中間 commit を頻繁化** (kill されても部分成果が残るように)
5. **末端 systematic bias** (`extrap mean = -16 at MD 9000+`): 改修 b では explicit な対応なし。Phase 5 post-proc で stage-aware regression を追加検討

## リスクと対策 (新規)

1. **karnakbaev artifact ライセンス** — Kaggle public dataset は default Apache 2.0 だが、karnakbaev/needless090/romantamrazov の各 dataset の `LICENSE` を **submit 前に必ず確認**。引用義務がある場合は `submission notes` に記載
   - 兆候: dataset DL 時に LICENSE が見当たらない / non-commercial 制約
   - 対応: 該当 dataset を blend から除外、自前再実装で代替

2. **artifact 再現性** — karnakbaev model を load しても Kaggle 環境で同 LB が出るとは限らない (lib version / dtype / random state)
   - 対策: Phase 3 1 週目で karnakbaev 単体推論 kernel push して LB を実測 (期待 ~10.784)
   - 兆候: 単体 LB が公表値と 0.5 以上ズレる
   - 対応: 自前再学習に切替

3. **TabICL の Kaggle 推論時間** — TabICL 2.1.1 regressor は in-context LM ベースで推論コスト高
   - 対策: Phase 3 で `time.perf_counter()` 計測、9hr 制約に収まる context size を選ぶ

4. **Top3 distill が遅延** — subagent B が時間取りすぎ
   - 対策: Day 9 (= +3 日) までに `docs/research/top3-distill.dense.md` 1.0 が出ない場合は移植 scope を Beam+PF+CB+TabICL の 4 要素に絞る

5. **exp003 が 12.5 を切らない** — tysig features の効きが弱い
   - 対策: Day 12 までに CV 12.5 切らない場合は exp004 (Beam Search) に直行 (exp003 は best feature subset で commit して止める)
